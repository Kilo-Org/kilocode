# TESTS.md — Kilo-specific test removal review

**Scope:** Upstream-merge PR merging opencode v1.18.13 (`a105350812`) into Kilo. Reviewed HEAD `cce22e608f`, pre-merge Kilo base `b135b4e10a`. Question: did this PR remove or weaken any Kilo-specific tests?

**Methodology:** Scanned the 390-file PR diff (`b135b4e10a..HEAD`): (1) all deleted files filtered to test-like paths, each checked for Kilo content and cross-referenced against upstream's own diff; (2) all 79 touched test-like files screened for `kilocode_change` marker-count deltas and removed `describe/it/test/expect` lines; (3) rename detection for test paths; (4) deletion scan for fixtures/snapshots/helpers under kilo paths; (5) every test file was classified as byte-identical to upstream v1.18.13 (45 files) or deviating (34 files) — for deviating files, every removed line was checked for Kilo content; (6) surviving Kilo test files checked for weakened assertions, with changes attributed to merge commits.

**Bottom line:** No Kilo-specific test was deleted. No file under `packages/opencode/test/kilocode/` (240 files), `packages/kilo-vscode/` tests, or any other kilo path was deleted or renamed. Zero removed lines containing Kilo references across all 79 touched test files. Two items below are flagged for human verification — both are low-severity.

## Findings

### 1. `packages/opencode/test/mcp/oauth-browser.test.ts` — Kilo CI-stability workaround dropped with upstream rewrite (flag: human verification)

- **What was removed:** The file was rewritten wholesale to match upstream v1.18.13 exactly (merged version is byte-identical to upstream). The rewrite deleted the old module-mock harness, which contained the file's only two `kilocode_change` markers. The marked block buffered the mock browser subprocess's `error` event until the consumer attached its listener, because "emitting on a timer races listener attachment on slow CI" — a Kilo-added fix for CI flakiness.
- **Did upstream remove it?** Yes — upstream v1.18.13 replaced the mock-based tests with a real `Bun.serve` OAuth MCP server plus an injected `McpBrowser` service layer; the mock the markers annotated no longer exists anywhere.
- **Coverage check:** No test cases were lost. All three scenarios survive in the new form (failure event published on browser-launch failure; no failure event on success; browser receives the discovered authorization URL), and assertions are equal or stronger — e.g. the custom `X-Custom-Header` assertion is now verified server-side on real `/mcp` requests instead of by inspecting mock transport constructor options. The race the Kilo workaround guarded against is structurally impossible in the new design (failure is delivered via `Effect.fail` through a service layer, not an `EventEmitter` mock).
- **Why flagged anyway:** The original markers existed specifically because of slow-CI races. The new tests depend on real HTTP round-trips and 5-second `awaitWithTimeout` budgets. No evidence of a problem in this review, but a human should keep an eye on CI flakiness for these three tests after the merge lands.

### 2. `packages/opencode/test/kilocode/issue-8656-stall.test.ts` — stall-detection timeout relaxed 30s → 60s (flag: human verification)

- **What changed:** One line in a Kilo-owned regression test: the poll budget in `stalled()` went from `30_000` to `60_000` ms. No assertion was removed; `expect(ready).toBe(true)` still gates the test.
- **Attribution:** Changed in `25f4b58d93 fix: address post-merge validation findings` — a deliberate Kilo-side post-merge adjustment, not an upstream change (upstream has no such file).
- **Why it matters:** This is a weakened-assertion pattern (step 5): the test now tolerates twice as much latency before declaring the session unstalled. If the v1.18.13 merge genuinely made stall recovery slower, this change masks it instead of surfacing it. Flagged for a human to confirm the bump was needed only for environment slowness (e.g. loaded CI runners) and not because post-merge stall behavior regressed.

Upstream deleted it in `638788f8d0 fix(app): move markdown parsing to worker`; the base file had zero `kilocode_change` markers and zero Kilo references. The deletion is also self-consistent: the tested 3-arg `preloadMarkdown(text, key, parser)` signature no longer exists (the surviving `markdown-cache.tsx:55` export takes 2 args), so the test would not compile. Side observation, not a merge defect: upstream left `preloadMarkdown` exported with no callers and no test coverage.

Kilo-specific assertions in the same files survived, e.g. `expect(model).toMatchObject({ providerID: "kilo", id: "kilo-auto/small" })` in `provider.test.ts:777`, the `@kilocode/kilo-gateway` describe blocks in `transform.test.ts`, and the Kilo provider-cost tests in `compaction.test.ts`.

## Limitations

- Marker counting catches `kilocode_change` and literal `kilo` strings; a Kilo-specific assertion written in purely generic terms (no marker, no kilo identifier) inside a shared test file would not be distinguishable from upstream content. The per-file upstream-diff comparison mitigates this: any removed line that upstream did not also remove was inspected, and none existed beyond the items above.
- The 45 test files byte-identical to upstream were not re-read line by line; by construction they contain no Kilo-specific removals (upstream's own test changes are out of scope for this report).
- This review is static; tests were not executed. Finding 1's CI-stability question and Finding 2's timeout justification can only be settled by observing the suites in CI.
