# Broken Pipeline Chains Review — upstream v1.18.13 merge (PR head cce22e608f)

## Scope and methodology

Reviewed the merge of upstream opencode v1.18.13 (a105350812) into Kilo (pre-merge base b135b4e10a; PR diff = 390 files) looking for end-to-end chains where Kilo functionality spans multiple files/layers and the merge may have silently dropped an intermediate link. For every `kilocode_change` hunk in the diff (located via `git diff -G kilocode_change`), each Kilo-introduced symbol (config key, param, field, event, message type, marker property) was traced from introduction → pass-through → consumption in the post-merge tree, cross-checking against `git show b135b4e10a:<path>` (pre-merge wiring) and `git show a105350812:<path>` (upstream's rerouting). Removed `kilocode_change` lines were extracted and each removal was accounted for. `bun run typecheck` passes in both `packages/opencode` and `packages/kilo-vscode`; per the brief, that does not clear any finding below.

## Findings

### 1. Grok reasoning-variant suppression was dropped; non-4.5 grok models now get effort variants

- **Chain:** model id containing `grok` → `ProviderTransform.variants()` → variant set advertised in UI/CLI → selected variant → `reasoningEffort()` / `options()` → `reasoningEffort` (xAI) or `reasoning.effort` (OpenRouter) sent in the request body.
- **Broken link:** Kilo's deliberate guard `if (id.includes("grok") && !id.includes("grok-4.5")) return {}` (wrapped in `// kilocode_change start/end`) is gone. It was removed in the compat commit `0fff61fa62` ("refactor: kilo compat for v1.18.13"), not by upstream — upstream never had the guard. No replacement exists in the merged tree.
- **Before:** base `transform.ts:767-771` returned `{}` for every grok model except grok-4.5 (grok-3-mini had its own block above, preserved).
- **After:** grok models that are not grok-3-mini fall through to the generic npm switch: `case "@ai-sdk/xai"` (`packages/opencode/src/provider/transform.ts:985-999`) yields `WIDELY_SUPPORTED_EFFORTS` mapped to `{ reasoningEffort }`; `case "@openrouter/ai-sdk-provider"` (`transform.ts:855-872`) yields `WIDELY_SUPPORTED_EFFORTS` mapped to `{ reasoning: { effort } }`. The `@kilocode/kilo-gateway` case (`transform.ts:835-846`) still returns `{}` for grok via its negative-id guard, so only the direct-xAI and OpenRouter paths changed.
- **Why silent:** everything typechecks; the change only manifests as a new variant picker and new reasoning params on grok requests (e.g. grok-4, grok-code-fast) that previously had none. If those models reject or mishandle effort params, requests fail or behavior shifts at runtime only.
- **Human verification:** confirm the removal was intentional in the compat pass (xAI may have since added effort support to newer grok models, making the old guard stale). If not intentional, restore the guard. Test: select a grok-4 / grok-code-fast model on the `xai` provider and on OpenRouter, inspect the advertised variants and the outbound request body's `reasoningEffort` / `reasoning.effort`.

### 2. `toPublicInfo` now silently drops any model that fails `Schema.is(Model)` from public provider responses

- **Chain:** provider state `models` (built from models.dev catalog, user config merge, OAuth plugin discovery such as github-copilot/modal, and Kilo's dynamic kilo-gateway fetch) → `toPublicInfo(provider)` → `/provider` API responses + SDK `Provider` type → extension model pickers.
- **Unverified link:** `packages/opencode/src/provider/provider.ts:1128` now filters `Object.entries(provider.models)` through `Schema.is(Model)(model)` before serializing. A model that fails the schema is dropped **silently** — no log, no error — so a Kilo- or plugin-built model missing a required field (or with a field of the wrong shape) would vanish from the public provider list while remaining in internal state.
- **Context:** the filter is upstream's addition (a105350812 has it identically), kept by the merge. All Kilo construction paths I traced produce conforming models: `fromModelsDevModel` (`provider.ts:1282-1302`), the config-merge `parsedModel` (`provider.ts:~1510-1560`, always sets `release_date`/`family`), copilot's typed `CopilotModel` build, and kilo-gateway models routed through `fromModelsDevModel`. Effect Schema structs tolerate excess keys, so Kilo extras (`endpoint`, `reasoningMode`, `family`, `mercury`) are safe. The risk is confined to any path that builds a model object without schema parsing that I did not enumerate.
- **Human verification:** diff `/provider` (or `kilo` provider list) output before/after the merge for a config that includes (a) a custom provider model in `kilo.json`, (b) github-copilot OAuth models, and (c) the dynamic `kilo` gateway models. Any model present internally but missing from the response indicates a schema-conformance drop; if found, the failure should be logged rather than silent.

### 3. Session-list `?directory=` no longer filters by the raw value; it is rerouted through instance resolution

- **Chain:** extension Agent Manager / multi-project clients → `GET /session?directory=<path>` → session list handler → `session.list({ directory })` → per-directory session storage. This is the load-bearing chain for Agent Manager worktree sessions sharing one backend.
- **Rerouted link:** `packages/opencode/src/server/routes/instance/httpapi/handlers/session.ts:72-75` now computes `const directory = ctx.query.directory ? yield* InstanceState.directory : undefined` instead of passing `ctx.query.directory` raw (base used the raw query value). `InstanceState.directory` resolves via `InstanceRef ?? Kilo capture()` (`effect/instance-state.ts:15-24`), where `InstanceRef` is provided per-request by `InstanceContextMiddleware` from `WorkspaceRouteContext` (`middleware/instance-context.ts:30-32`), which in turn comes from `WorkspaceRoutingMiddleware`'s `defaultDirectory` = `?directory=` param → `x-kilo-directory` header → `process.cwd()` (`middleware/workspace-routing.ts`, `defaultDirectory`).
- **Assessment:** the chain is wired (the plain `?directory=` param does reach `InstanceRef` via the middleware, and the session group applies both middlewares at `groups/session.ts:480-481`). What changed is that the value now passes through `InstanceStore.load({ directory: decode(route.directory) })`, which may normalize/resolve the directory (project-root resolution, symlink/realpath handling) rather than using the client-supplied string verbatim. This is upstream's redesign, identical in a105350812.
- **Human verification:** with Agent Manager, list sessions for a worktree whose path differs from the main checkout (ideally a symlinked or nested path) and confirm the returned sessions are scoped to that worktree, not to `process.cwd()` or a resolved parent. A regression here shows as worktree session lists returning the main project's sessions.

## Limitations

- Typechecks pass for `packages/opencode` and `packages/kilo-vscode`; the full test suites were not run, and a compile pass does not prove chain integrity (per the brief).
- The models catalog source switched from `https://models.dev` to `https://models.opencode.ai` (`core/src/models-dev.ts:169`, upstream change). Whether the new source serves `reasoning_options` (which powers `reasoningVariants`) could not be verified from this environment (no outbound network). If absent, variants silently fall back to heuristics.
- The kilo-ui → `@opencode-ai/ui` re-export facade was spot-checked (context, i18n, markdown, diff, dialog, tooltip, select), not exhaustively diffed against webview imports.
- Two parallel markdown pipelines now exist: `packages/ui` (KiloTheme, used by the Kilo webview via kilo-ui) and `packages/session-ui` (OpenCodeTheme, consumed only by `packages/storybook` in this repo). Divergence is expected but worth knowing.
- `@tanstack/solid-virtual` catalog pin was bumped (3.13.28→3.13.32) and its two Kilo patch files (`solid-virtual`, `virtual-core`) deleted. The package has no dependent workspace in either base or head (dormant catalog entry), so the patch loss has no runtime effect today; the leftover pin is inconsistent housekeeping worth confirming.
- `packages/opencode/src/plugin/modal/*` (new upstream plugin) was not deep-reviewed against Kilo behaviors.
- Cloud-schema mirroring of config keys (per repo fork rule) lives in a separate repo and was not verifiable here; no new kilocode_change config keys were added by this merge (`subagent_depth` is upstream's).
- The JetBrains plugin is untouched by this PR and was not reviewed.
