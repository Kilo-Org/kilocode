Add Security Auto Mode (`experimental.security_auto`, off by default): a security layer that adjudicates side-effecting tool calls as ALLOW / ASK / DENY before the permission prompt. It blocks destructive, credential-exposing and policy-tampering actions with a structured result the agent can recover from, forces an interactive prompt for opaque or unparsed shell commands, and adds seven independently switchable evidence layers on top: pre-install package provenance checks, sensitive-read-to-outbound egress protection keyed on session state, capability and provenance classification for MCP and custom tools, secret detection in ordinary workspace content, a trust boundary that keeps repository-controlled project code from executing before it is approved by content digest, a permissioned runtime that evaluates approved project extensions in a confined host process whose reads, writes, network access and process spawning go through the same engine, and a semantic layer that asks the model Kilo is already configured with whether untrusted text directed the action or whether the action has nothing to do with the request. Evidence is folded monotonically, so no layer — the semantic one included — can weaken a decision, and with no model configured the semantic layer contributes nothing. See `docs/security-auto-mode.md` for the architecture and `docs/security-auto-mode-benchmark.md` for the adversarial evaluation.
