### Pre-existing UI discrepancy

The VS Code **Open config file** picker still enumerates `~/.opencode` and project `.opencode` files and marks existing entries as loaded (`packages/kilo-vscode/src/kilo-provider/config-file.ts:37-52,62-69,94-109`; displayed by `packages/kilo-vscode/src/kilo-provider/open-config.ts:30-53`). It does not restore runtime fallback and does not change this merge verdict.

## Notable Non-Findings

- **No `.opencode` directory fallback was restored.** Stable discovery returns `${XDG_CONFIG_HOME}/kilo`, project/home `.kilocode` and `.kilo`, primary-checkout equivalents, and explicit `KILO_CONFIG_DIR` (`packages/opencode/src/config/paths.ts:23-40`). Core V2 discovers only direct compatible files plus `.kilocode`/`.kilo`, then filters directory entries again (`packages/core/src/config.ts:174-206`). Pristine upstream v1.18.0 uses `${XDG_CONFIG_HOME}/opencode`, `.opencode`, and `OPENCODE_CONFIG_DIR`; the adapted head replaces those runtime candidates rather than adding Kilo paths beside them.
- **Compatible filenames are not forbidden-directory fallback.** `opencode.json` and `opencode.jsonc` remain supported filenames in the Kilo XDG root, as direct project files, inside `.kilocode`/`.kilo`, and in managed Kilo directories. Stable also retains global `config.json`; Core V2 retains `config.json` in its location-name set. This compatibility never makes project `.opencode/` or `${XDG_CONFIG_HOME}/opencode` a load root. Dedicated TUI config remains `tui.json[c]` under allowed roots.
- **Precedence remains Kilo-specific and tested.** Stable filesystem order is global Kilo config, `KILO_CONFIG`, direct project files, primary-checkout fallbacks, active project/worktree directories, `KILO_CONFIG_DIR`, `KILO_CONFIG_CONTENT`, and then applicable account/managed sources. Within paired directory roots, legacy `.kilocode` loads before canonical `.kilo`; active-worktree config wins over primary fallback; `KILO_CONFIG_DIR` wins over both. Core V2 applies global config, direct project files from outer to inner, then `.kilocode` and `.kilo` directory files from outer to inner, with `.kilo` last at the same level. Real-loader sentinel tests confirmed these outcomes and that `.opencode` values stay absent.
- **XDG and environment routing remain Kilo-only.** `Global.Path.config` is `${XDG_CONFIG_HOME}/kilo` because `app = "kilo"` (`packages/core/src/global.ts:12-25`). Runtime flags expose `KILO_CONFIG`, `KILO_CONFIG_CONTENT`, `KILO_CONFIG_DIR`, `KILO_TUI_CONFIG`, and `KILO_DISABLE_PROJECT_CONFIG`, with no `OPENCODE_CONFIG*` aliases (`packages/core/src/flag/flag.ts:38-47,131-142`). Managed directories are `/etc/kilo`, `/Library/Application Support/kilo`, and `%ProgramData%\kilo`; the retained `ai.opencode.managed` plist domain is an existing managed-preference identifier, not a config-directory fallback (`packages/opencode/src/config/managed.ts:8,20-32,43-65`).
- **Commands, agents, plugins, tools, skills, and TUI inherit the filtered roots.** Stable command/agent/plugin scanning occurs inside the loader's directory loop (`packages/opencode/src/config/config.ts:713-805`); custom tools and skills consume `config.directories()` (`packages/opencode/src/tool/registry.ts:225-239`, `packages/opencode/src/skill/index.ts:245-261`). TUI applies the same `.kilo`/`.kilocode`/`KILO_CONFIG_DIR` filter (`packages/opencode/src/config/tui.ts:186-234`). Core V2 plugins and skills consume only `Config.Directory` entries (`packages/core/src/config/plugin/external.ts:42-71`, `packages/core/src/config/plugin/skill.ts:20-45`). The upstream `customize-opencode` source remains dormant but is not registered; Kilo's `kilo-config` builtin remains registered in stable (`packages/core/src/plugin/internal.ts:107-120`, `packages/opencode/src/kilocode/skills/builtin.ts:14-20`).
- **Legacy Kilo migration is preserved without re-enabling OpenCode roots.** Modes, rules, workflows, MCP settings, and `.kilocodeignore` migration continue to read documented Kilo legacy locations. The `.opencode` scanner only builds a move-config notification and never returns load candidates (`packages/opencode/src/kilocode/config/config.ts:549-604`). Public settings and CLI docs explicitly warn that `.opencode` directories are not loaded (`packages/kilo-docs/pages/getting-started/settings/index.md:30-35`, `packages/kilo-docs/pages/code-with-ai/platforms/cli.md:342-348`).
