# Kilo v2 release and contributor policy review

Comparison: Kilo v1 (`origin/main`, `46e4dd47e52`), Kilo v2 (`origin/v2`, `1f62fd676d9`), and the OpenCode v2.2.7 pin. This is a spot-check of source notices, release packaging, and public contributor policies, not a legal opinion or a full dependency audit.

## Fixed in this worktree

- Restore `Copyright (c) 2026 Kilo Code` alongside `Copyright (c) 2025 opencode`. The root [MIT license](../../LICENSE) and [VS Code copy](../../packages/kilo-vscode/LICENSE) match v1 verbatim. The project's license terms are unchanged.
- Include the full MIT text in the npm launcher, each platform CLI tarball, the schema/protocol/client tarballs, and release and snapshot VSIXs. Preserve existing Linux sandbox notices and the extension's Continue license. The publish flow checks packed npm and preview VSIX contents; `"license": "MIT"` metadata alone is not a substitute for the text. Review the affected published v1 SDK/plugin tarballs as well: those also omitted the license file.

## Before shipping affected builds

| Finding | Recommended change |
|---|---|
| **FFmpeg in v1 and v2 VSIXs.** Both use the same [pinned binaries](../../packages/kilo-vscode/script/ffmpeg-helper.ts) and copy only the executable from the npm tarballs. Embedded configure flags in the exact macOS x64, Linux x64/ARM64 (also used for Alpine), and Windows x64 binaries include `--enable-gpl --enable-version3`. macOS ARM64 also includes `--enable-nonfree`; FFmpeg describes such builds as unredistributable. The v1 SBOM's uniform LGPL label does not match these binaries. | Hold affected VSIX releases pending replacement or clearance. Remove the macOS ARM64 binary or replace it with a build cleared for redistribution. For any GPL build retained, confirm the exact license, ship the required notices and make the exact corresponding source and build materials available via a permitted distribution method. Validate per target. See [FFmpeg's license and redistribution guidance](https://ffmpeg.org/legal.html). Review already-published v1 and v2 packages with release owners. |
| **Linux sandbox helper.** Both branches ship [the sandbox runtime](../../packages/kilo-cli/script/kilocode/kilo-sandbox-network.ts) with its Apache 2.0 license. The pinned `@anthropic-ai/sandbox-runtime@0.0.63` ships `apply-seccomp` for x64 and ARM64; the package build uses static linking and the binaries contain glibc code. No separate glibc notices or source/relinking materials were found in the inspected packaging. | Confirm the exact libc version, build inputs, and applicable LGPL conditions; supply the relevant notices and source/relinking materials, or replace the helper with a verified alternative. Review this for Linux CLI and VSIX distributions. |
| **Other reviewed components.** The Linux Bubblewrap payload already carries its pinned source tarball, build recipe, LGPL text/notices, and musl copyright. The [Continue Apache 2.0 text](../../packages/kilo-vscode/THIRD_PARTY_LICENSES/continue.txt) matches v1 and is present in the built VSIX. | Preserve these in every artifact that includes the code. For Continue-derived files, spot-check retained attribution and modified-file notices against Apache 2.0 §4. Check that the separately licensed Belladore.ai tokenizer's MIT notice survives bundling. |
| **Other release paths.** The [alpha installer](../../script/kilocode/install-alpha.ts) extracts the CLI archive but copies only `bin/`, not the archive-root `LICENSE`. v1 has additional channels that the current v2 preview workflows do not publish to. | Preserve `LICENSE` in alpha installed payloads. At cutover, verify standalone archives, JetBrains bundles, containers, and package-manager builds as they come online. Generate a per-artifact SBOM and notice inventory from shipped files, including bundled native dependencies and Tree-sitter grammars; a lockfile inventory alone will miss these. |

## Contributor and public policies to port

| Surface | v1 to v2 recommendation |
|---|---|
| [`CONTRIBUTING.md`](../../CONTRIBUTING.md) and public contributor docs | Replace OpenCode's `dev`, `dev:live`, and upstream issue instructions with Kilo's `v2` target, isolated `bun dev`, [migration principles](../principles.md), and [repository checks](../../AGENTS.md). Keep v1's issue-first guidance and contributor ownership of AI-assisted work; link `REVIEW.md`. Document when to regenerate from `packages/client`. Do not copy v1 Changesets, SDK or build instructions into v2. Scope the public Kilo contributor docs by version. |
| [PR template](../../.github/pull_request_template.md) | Keep v1's linked issue and concrete `## Proof`: commands/results or a specific blocker and substitute evidence, before/after UI proof when applicable, and who ran the checks. Remove generic automatic-rejection claims unless owners confirm the enforcement actually runs. |
| [Issue forms](../../.github/ISSUE_TEMPLATE) | Restore the Kilo component field and optional Kilo version, Kilo support links, and a private security-reporting route. Decide whether to restore v1's Question form or route questions to Kilo Discord. Don't restore the v1 share-link prompt until v2 supports sharing. Confirm which default branch serves the forms at cutover. |
| `CODE_OF_CONDUCT.md` | v2 lacks the v1 Contributor Covenant 2.0 policy. Restore the v1 text with its attribution and link it from the contributor guide and README after confirming who monitors `hi@kilo.ai` and handles enforcement. |
| [`SECURITY.md`](../../SECURITY.md) | Replace OpenCode's report destinations for Kilo issues with [Kilo's disclosure policy](https://kilo.ai/security) and `security@kilo.ai`. Update the threat model for the v2 service and sandbox rather than copying v1 wholesale. Link this route from the issue forms and Marketplace README. |
| [Repository README](../../README.md) and [VS Code README](../../packages/kilo-vscode/README.md) | Use Kilo support, install, and docs links appropriate to each release channel. Link the MIT license and preserve OpenCode credit. Link [privacy](https://kilo.ai/privacy), [service terms](https://kilo.ai/terms), and [Kilo name/logo guidance](https://kilo.ai/docs/contributing/ecosystem) separately from the software license. Confirm privacy and telemetry wording with the owners; do not import upstream or v1 claims about data handling. |
| Ownership and contribution agreements | Replace stale OpenCode [`CODEOWNERS`](../../.github/CODEOWNERS) entries with approved Kilo owners before cutover; verify GitHub rulesets, apps and review/triage automation before promising response times or enforcement. No CLA or DCO requirement was found in the checked v1 or v2 repository guidance/workflows; adopting one is a separate maintainer/legal decision, not an MIT requirement. |

Keep policy changes separate from the MIT packaging fix. Prefer short GitHub entry points that link to Kilo-owned guidance; track unavoidable shared-file edits in the upstream patch baseline so they survive syncs.
