# Kilo v2 migration tracking

Planning, evidence and validation material for moving Kilo onto the upstream opencode v2 runtime. The work lands on Kilo's integration branch, `origin/v2` (not to be confused with opencode's `upstream/v2`).

## Start here

| Need | File | Class |
|---|---|---|
| What is ported, open or dropped, per feature, measured against the v1 target | [progress/README.md](progress/README.md) | generated |
| Shared facts, pinned refs, decisions, working model, conventions | [plans/migration-context.md](plans/migration-context.md) | living |
| Host strategy: why Kilo code leaves upstream files, how one change is placed (plugin hook, host, seam, patch), guarantees when upstream changes, order of work | [plans/v2-host-strategy.md](plans/v2-host-strategy.md) | living |
| Epics, gates, critical path (Part A); units, dependencies, acceptance and status (Part B) | [plans/kilo-v2-migration-plan.md](plans/kilo-v2-migration-plan.md) | living |
| Baseline health of the pinned upstream base | [technical-notes/baseline/pinned-v2-baseline.md](technical-notes/baseline/pinned-v2-baseline.md) | living |
| v1 vs v2 API and session model differences | [v2-v1-schema-diffs.md](technical-notes/baseline/v2-v1-schema-diffs.md), [v2-v1-session-diffs.md](technical-notes/baseline/v2-v1-session-diffs.md) | living |

## Structure

```text
migration-tracking/
├── progress/         # generated progress map (README.md, progress.json) and its inputs (features.json, dispositions.json)
├── plans/            # context brief and the migration plan (living); superseded plans and working log (archive/evidence)
├── discovery/        # feature inventory, epic taxonomy, unit register, doc inventory (frozen evidence, 2026-10-11)
├── marker-audit/     # 816-file v1 assessment and shared-change inventories (evidence)
├── technical-notes/  # parity notes, contracts, incidents (evidence unless marked living)
├── test-plans/       # scenario plans (stale; rewrite in U-L4-01)
├── github-drafts/    # publication drafts for the tracking issue (archive)
└── assets/           # screenshots of the archived port (archive)
```

## Rules for this collection

- One canonical place per fact. Decisions and refs live in `migration-context.md`; sequencing and unit status live in the plan; per-feature evidence lives in `discovery/` and `technical-notes/`.
- Evidence files are frozen: cite them, do not maintain them. Notes measured against the archived port's upstream base must have their seam claims re-checked at the current base before reuse.
- `progress/README.md` and `progress/progress.json` are generated by `bun script/upstream/progress.ts`; CI fails when they are stale. Edit `progress/features.json` and `progress/dispositions.json` instead.
- Superseded files carry a banner at the top. The class of every seeded file is recorded in [discovery/doc-inventory.md](discovery/doc-inventory.md).
- A listed test is a requirement, not proof that it passed. A local pass is never recorded as end to end.
- Keep markdown tables compact and do not run prettier on these files.
