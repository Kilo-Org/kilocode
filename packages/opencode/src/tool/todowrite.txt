Create and maintain a structured task list for the current coding session. Tracks progress, organizes multi-step work, and surfaces status to the user.

## When to use
Use for substantial multi-step work, multiple requested deliverables, or an explicit request for a task list. Skip simple tasks, informational questions, and work where tracking adds no value.

Track meaningful milestones rather than individual tool calls. Update the list when a milestone completes, the scope changes, or a blocker appears; routine intermediate actions do not need separate updates.

## States
- `pending` - not started
- `in_progress` - actively working (exactly ONE at a time)
- `completed` - finished successfully
- `cancelled` - no longer needed

## Rules
- When creating a list, mark the current milestone `in_progress`. At a milestone transition, mark finished work `completed` and the next milestone `in_progress` in the same update.
- Mark `completed` only after the required work is actually done, including any required verification. Never based on intent.
- Keep exactly one `in_progress` while work remains
- If blocked or partial, keep it `in_progress` and add a follow-up todo describing the blocker
- Preserve user-provided commands verbatim (flags, args, order)
- Keep milestones specific and actionable. Before finalizing, reconcile the list with what was actually completed or remains blocked.
