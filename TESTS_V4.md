## New findings

### 1. New `shell-env.test.ts` credential-isolation test fails deterministically on macOS (medium — flag: human verification)

- **What:** `packages/opencode/test/kilocode/tool/shell-env.test.ts` (new in the delta via main-line `4e36297668`, PR #12600) sets all five backend-secret env vars to sentinel values — including `KILO_CONFIG_DIR=/secret/config` — then executes a real ShellTool command asserting the child sees none of them. Locally the test fails before reaching the assertion: the in-process config loader resolves `Config.paths` (`packages/opencode/src/config/paths.ts:39` includes `Flag.KILO_CONFIG_DIR` verbatim) and attempts `FileSystem.makeDirectory("/secret/config")`, dying with `EROFS: read-only file system, mkdir '/secret'` (stack: `Config.get` at `tool/shell.ts:712` → `Config.loadInstanceState`). Reproduced twice; batch result 72 pass / **1 fail**.
- **Why it's environment-deterministic:** macOS always returns EROFS for the SIP-protected root volume (sandboxed or not); non-root Linux returns EACCES. The test can only pass where the test process may `mkdir /secret` — e.g. rootful containers. CI's matrix includes a `macos-15` shard with `packages: true` (`.github/workflows/test.yml` line 67), so if this file is scheduled on that shard it should fail there too — yet the test merged to main via PR #12600, so either the macOS shard does not run this file, or CI tolerated it. The fixture should use a writable sentinel (e.g. a tmp path, or drop only `KILO_CONFIG_DIR` to a tmpdir) — the credential keys themselves are fine as inert strings; only `KILO_CONFIG_DIR` is acted on by the backend.
- **Provenance note:** the file is byte-identical between base tip and head (md5 `ce77dc26…`); it is base-branch content entering the round-3→4 delta via the base merge, not a merge artifact. It still lands in this PR's overall test surface.
- **Action for a human:** confirm whether macOS CI runs this suite; if the failure is real there, fix the fixture path (or gate the mkdir) before the merge makes it every macOS contributor's local failure.

### 2. httpapi-pty e2e spawn-dimension test added and reverted inside the delta — dimension-application coverage lost (low — flag: human verification)

- **What:** `db47401365 test(pty): add end-to-end spawn dimension test` (Aug 7 12:59) added a marked test spawning a PTY with `size: { cols: 50, rows: 20 }` running `stty size`, reading the websocket stream, and asserting the output contains `"20 50"` — the only end-to-end proof that the server applies requested dimensions to the spawned PTY. `039c8e4888 test(pty): revert fast-exiting socket test in httpapi-pty` (Aug 7 13:08, nine minutes later, empty commit body) removed exactly that block. Both are main-line commits (context branch `fix/macos-ci-pty-flakiness`) entering via the base merge; net delta effect on the e2e test is zero.
- **What remains:** (a) the marked block in the file's main test still POSTs `size: { cols: 50, rows: 20 }` on create (and `{ cols: 80, rows: 24 }` on update) but asserts only status 200 and `matchObject({ title, command, status })` — schema acceptance, not application; `Pty.Info` does not echo size, so no response-level assertion is possible without a schema change; (b) client-side tests pin the ordering: `agent-manager-terminal-routing.test.ts` ("applies initial create dimensions and queues resize messages before creation settles") and `agent-manager-terminal-layout.test.ts` ("fits and forces the initial PTY dimensions before socket attach", "re-sends dimensions when an optimistic terminal receives its PTY"). The source path is implemented and marked (`packages/core/src/pty.ts` lines 217–224 pass `input.size?.cols/rows` into `spawn`).
- **Assessment:** the revert's likely cause is the fast-exiting `stty size` process racing websocket attach on loaded CI (the commit title says as much) — legitimate flake hygiene, but the property "server applies spawn dimensions" is now untested anywhere. A robust re-pin would use a long-lived process (e.g. `sh -c 'stty size; sleep 5'`) or assert a resize event, instead of dropping the dimension.
- **Action for a human:** confirm the flake diagnosis and decide whether the e2e dimension check is re-pinned or consciously left to client-side coverage.
